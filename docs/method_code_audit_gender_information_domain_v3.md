# 性别化信息领域参与研究：方法与代码审计（v3）

## 审计范围

本次审计从 `slurm/run_all.slurm` 出发，追踪四张分析表、结果层、稳健性层、绘图数据和现有图形，重点核对 `docs/paper_draft_gender_information_domain_participation_v2_long.md` 中的数据、变量与方法表述。审计基于当前本地代码、结果表和运行记录，未重新处理全年帖子数据。

## 结论

现有代码已经形成结构完整的用户级分析框架，文本清理、零分母处理、用户级模型、领域交互和结果留痕均有明确实现与测试覆盖。核心方法可以支持“男性编码与女性编码账号在两个信息领域中的可见参与差异”这一描述性研究问题。

正式投稿前仍有三项必须解决的问题。第一，`run_all.slurm` 的主结果层使用 225,339 个全账号，209,871 个个人账号只作为稳健性变体运行，现有主图也属于全账号口径。第二，转发事件时间戳日期与文件名日期的分片不一致率约为 49%—76%，而月度、活跃天数和活跃月份均按文件名日期生成。第三，现有主结果和稳健性运行记录均标记为脏工作区，且同一 `run_id` 下出现不同 Git 版本，当前结果无法仅凭提交号精确复现。

在这三项问题解决前，个人账号四项核心 M0—M2差异可以作为已经复核的结果使用；月度稳定性、参与持续性、延迟扩展、个人账号组合分析和“完整稳健性套件”应标注为待确认或全账号对照，不能与个人账号主结果合并叙述。

## 已确认正确的实现

### 1. 文本与表达帖口径

- 转发链只在字面 `//@` 出现时截断，并先于链接清理执行，避免把用户自己的 `@提及` 误删。
- 表达帖统一定义为有非空清洗文本的原创帖或带新增文字的转发帖；纯转发、纯图片和纯链接不进入内容比例分母。
- 两份词表采用最左最长、区间不重叠的匹配方式，避免嵌套词重复计数。
- 没有有效文字帖时，内容比例保留为缺失值而非写成 0。

### 2. 来源转发事件

- 仅保留实际转发记录，以被转发原帖作者 ID 匹配来源名单。
- 来源账号自身的转发被排除，同一微博—领域的跨文件重复记录会被删除。
- 延迟只在已实现的转发事件中定义，代码同时保留 720 小时上限和不设上限两种口径，并以用户为聚类单位计算区间。

### 3. 用户级模型

- 进入模型使用二元 Logit，并报告概率尺度的平均边际效应，而非只报告不可跨模型比较的发生比。
- 正计数采用两部分模型：进入与正计数分开，正计数部分使用零截断负二项；拟合失败会保留为空行并记录原因。
- 内容比例使用带稳健协方差的分数 Logit，允许 0 和 1 边界值。
- 性别 × 领域检验将同一账号的两个领域记录转成长表，并使用按账号聚类的 GEE，直接估计两个性别差异之间的距离。
- M0、M1、M2 的协变量层次和样本损失均写入结果表；M2 的样本收窄没有被静默隐藏。

### 4. 测试结果

`gender_domain/tests` 共 753 项测试全部通过。警告主要来自测试夹具中的完全分离、拟合不收敛和 pandas 未来版本降型提示；代码会对正式结果中的拟合失败留痕。当前核心强度结果中仍有 5 行拟合失败，因此来源转发次数只适合作为补充结果。

## 必须修正的问题

### 1. 主样本与主结果流水线不一致

`run_all.slurm` 的 `describe`、`models_core`、`models_interaction`、`models_combination`、`models_temporal` 和 `export_figure_data` 均直接读取全账号表 C。运行记录显示主结果的 `n_users=225339`。个人账号样本通过稳健性模块的 `exclude_institutional_accounts` 变体得到，`n_users=209871`，其中男性 41,300 人、女性 168,571 人。

v2 摘要中的个人账号 M1 结果可以在该变体中逐项复核：公共来源进入为 +2.28 个百分点，演艺来源进入为 -0.80 个百分点，公共事务帖子比例为 +3.93 个百分点，明星帖子比例为 -3.06 个百分点。两个领域的差异距离分别为 3.16 和 8.34 个百分点。

现有 `20260819_fig1` 至 `fig6` 由全账号结果层生成。它们只能标为“全账号对照”，不能作为个人账号主图。正式主图需直接从个人账号主样本结果生成，并在文件名、manifest 和图注中标记 `personal_accounts_main`。

### 2. 月份变量存在高比例日期不一致

表 A 和表 B 的 `date`、`month` 均取自输入文件名，而不是帖子时间戳。延迟清理记录显示，转发时间戳换算日期与文件名日期在 11 个分片中的不一致率约为 49%—76%。该比例远超时区边界能够解释的范围。

这一问题会影响按日或按月定义的指标，包括活跃天数、活跃月份、用户—月份面板、月固定效应、留一月份检验和参与持续性。论文暂不能写“各月份均保持同一方向”或把活跃天数、活跃月份解释为自然日/月行为，除非先确认文件名代表何种日期，并使用真实帖子时间重新构造时间变量或证明二者的对应关系。

### 3. 运行版本无法精确复现

主结果、时间模型和绘图数据的 manifest 记录 `git_sha=9ffc9d7` 且 `git_dirty=true`；个人账号稳健性结果记录 `git_sha=fc2fac7` 且 `git_dirty=true`。两者沿用了同一个 `run_id=14538662`。因此，同一个 `run_id` 只证明人为指定了相同批次标签，不能证明代码版本相同。

正式结果应在干净工作区重新运行，保存完整提交号、词表和来源名单指纹，并要求一个结果批次内所有阶段的 Git 版本一致。运行时若 `git_dirty=true`，正式流水线应直接停止或生成不可投稿标记。

## 需要在论文中改正的具体表述

### 延迟样本量

v2 将“删除 19,125 条”误写为“保留 19,125 条”。720 小时上限口径下，输入 184,537 条候选事件，删除 19,125 条，保留 165,412 条，占 89.6%。其中删除包括跨年前源帖 3,671 条、超过 720 小时 727 条和重复用户—原帖—领域事件 14,727 条。

### M2 的解释

M2 不是在同一批 225,339 个账号上“进一步比较账号资料”。它只使用画像完整的 155,977 个全账号；个人账号变体的 M2 使用 141,095 个进入模型账号，内容比例模型为 140,391 个。M2 与 M0/M1 的差异同时包含协变量调整和样本改变，正文必须并列报告样本量，不能只把系数变化归因于“控制了资料”。

### 机构账号分类

个人账号样本依赖 `verified_type` 为 1—7 时认定为机构账号的假设。目前没有微博官方码表，代码和运行记录也明确将其标记为假设。正式稿应把这一规则写为研究者操作化，并补充人工核验样本、各编码的账号示例和错分率。

### 来源名单的历史适配

公共来源以 2025 版互联网新闻信息稿源单位名单回溯识别 2020 年微博账号。该做法提供统一候选框，但不能自动证明账号在 2020 年具有同一身份。正式稿需报告历史账号身份核验、昵称变更处理、匹配规则和遗漏风险。

### 词表语境效度

人工审核确认的是词条属于目标领域，不等于每次字符串命中都构成目标语境。当前匹配不做中文词边界或命名实体消歧。600 条分层语境样本尚未完成编码，投稿前应报告精确率、主要误判类型和编码一致性。

### 来源比例的上限截断

用户表将“领域来源转发数 ÷ 全部转发数”超过 1 的值直接截为 1。理论上，同一数据口径下分子不应大于分母。正式运行应记录发生截断的用户数并解释来源；若来自表 A/B 覆盖不一致，应先修复分母或限定共同事件集，不宜依靠截断隐藏不一致。

### SLURM 续跑条件

`run_all.slurm` 判断表 A、表 B 是否完成时只检查 `month=12.parquet`。如果 12 月分片存在而其他月份缺失，整个阶段会被跳过。正式脚本应检查所有预期月份或验证 manifest 中的月份集合，再允许结果层继续运行。

## v3 写作口径

1. 主体称为“男性编码账号”和“女性编码账号”；在个人账号样本且完成账号类型核验后，才谨慎使用“男性用户”和“女性用户”。
2. 研究结果统一称为描述性差异或调整后关联，不使用“性别影响”“导致”或“控制后的净效应”。
3. 四项个人账号核心结果作为当前主结果；全账号图、组合、月度和延迟结果放入对照或开发附录，并清楚标注样本边界。
4. 方法部分按“数据与样本—变量生成—统计模型—稳健性与运行边界”展开，每一步报告输入、规则、样本量和估计量。
5. 将日期不一致、机构编码、2025 名单回溯和语境编码写为可检验的测量边界，不用笼统的“数据限制”带过。
